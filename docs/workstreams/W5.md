## Done so far
All of this is real and was checked against real SUMO runs (TraCI backend) or the committed result files.

- **Experiment store** `manzil/store/` (README there): SQLite behind the `ExperimentRepository` interface; tables follow the D2 data dictionary (scenario, run, metric_sample, mission, route_version, priority_event, video_job, observation, artifact). Importer for batch run folders, live dashboard runs and the V.4/V.5 tracking results. Importing all committed results: **375 runs, 13,690 metric samples, 255 missions, 274 route versions, 5,769 priority events, 40 video jobs, 2,477 observations, 1,009 artifacts** in about 1.6 s (`results/fyp2/dashboard/store_summary.json`). Re-import is idempotent (content checksum).
- **FR-18 comparison** (`manzil/store/analytics.py`): groups by experiment arm, mean/SD/95 % t CI, paired differences on matched (profile, seed), comparability warnings (network, warm-up, window, metric version, mixed profiles, unmatched seeds, excluded runs). Reproduces `results/phase2/comparison/summary.json` exactly (test) and the Phase 4 heavy result (DQN 155.68 s, −17.25 s ± 6.13 vs fixed-time, as in `results/phase4/comparison/summary.json`).
- **FR-19 export**: `python -m manzil.store export ... --out x.json|x.csv` and `POST /api/export`; format documented in `manzil/store/README.md`. Samples: `results/fyp2/dashboard/export_phase4_heavy.{json,csv}`.
- **FR-02 pause/resume**: `POST /api/run/pause|resume`; while paused SUMO is not stepped, the state stays fresh, commands (close road, dispatch) still run; pauses are written to `summary.json`.
- **FR-16 warnings** in every state (`warnings` list; banner on every screen, with icon + label, not colour alone):
  - `stale`: no new state for 2 s while running (server side, `age_s`), plus a browser-side check;
  - `invalid`: safety-monitor violation, invalid snapshot, or ambulance with NO_ROUTE;
  - `disconnected`: SUMO connection lost (server) or API unreachable (browser);
  - `fallback`: DQN decisions held by its FR-20 fallback.
  Each was produced for real in tests and screenshots: SIGSTOP of the SUMO processes (stale), SIGKILL of SUMO (disconnected, test), stopping the API (disconnected, screenshot), closing both roads into C2 (NO_ROUTE), operator fault injection `POST /api/run/fault {"kind":"rl_loss"}` (fallback).
- **G01 validation** (`manzil/api/validation.py`, `POST /api/run/validate`): per-field checks (scenario, profile, controller/checkpoint sha256, seed, duration, mission route, incident, notes on warm-up and video). `/api/run/start` refuses configs with errors (422). G01 can also plan a mission and a road closure that run at their set time.
- **Dashboard** (`dashboard/src/`): five screens G01–G05 with hash navigation; G02 map + run control + network chart + event timeline; G03 live intersection detail (approaches with units, signal owner, requested vs applied controls) and prepared DETRAC perception results with provenance (model sha256, tracker, kernel, ground-truth source, "not live", "no calibration"), counts vs truth and queue-proxy chart; G04 dispatch, route versions with cost/trigger, earlier routes dashed on the map, routing log, corridor lifecycle; G05 study/profile filters, comparability panel, strip plot with mean and CI, stats + paired table, seed coverage, run list with include/exclude, export buttons.

## Decisions
- **SQLite, not PostgreSQL** (D2 proposed PostgreSQL behind a repository interface): one file, no server, works on the laptop and in the cloud; the interface keeps a later PostgreSQL implementation possible. The database is a derived index: `runs/manzil.sqlite` (git-ignored) can be deleted and rebuilt from the run folders at any time.
- **Run key = run folder path**, because `run_id` in manifests is not unique across studies.
- **Experiment arm** = run label, else `controller[:plan]` (same naming as `manzil.experiments.batch`); otherwise `fixed_time` and `fixed_time:equal` would be pooled.
- **ControlDecision rows not stored**: `applied_controls.csv` is not committed for batch runs. Live G03 shows requested vs applied controls from the running safety filter instead.
- **G03 shows prepared UA-DETRAC results**, labelled as recorded video, not live, not connected to SUMO, no calibration (D2 separate evidence paths). Lahore results from W2 can be added with the same importer once they exist.
- **Fallback demonstration by fault injection**: `rl_loss` replaces the DQN policy with one that raises, so the controller's own FR-20 path runs (no change to `manzil/control/dqn.py`, owned by W3). It is labelled "fault injected by the operator" everywhere.
- **Live runs have no warm-up**: G01 shows this as a warning; live runs are demonstrations, not protocol runs, and carry no metric version, so G05 warns when they are compared.
