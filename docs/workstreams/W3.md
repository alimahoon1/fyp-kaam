# W3 Full evaluation protocol + DQN robustness
Status: done (cloud session, branch `claude/w3-protocol`, 15–16 Nov 2026)

## Done so far
All numbers below are real SUMO runs on the **synthetic** 3×3 grid. Full tables are in `results/fyp2/protocol/README.md`.

- **Code** (17 tests in `tests/test_w3_protocol.py`):
  - `manzil/scenarios/demand.py`: held-out profiles `uneven_ew`, `tidal`, `peak` in `HELDOUT_PROFILES`, kept out of `PROFILES` so training and tuning cannot use them. Adds per-heading rates, a time-varying schedule (thinning), and `FringeEdge.heading`. The four training profiles give identical trips to Phase 1 (checksum test).
  - `manzil/experiments/protocol.py`: protocol runner for any scenario folder. 10 evaluation seeds (20–29); fixed-time plan for held-out profiles chosen on dev seeds; failed runs kept; red-interval fairness metrics; paired 95 % CIs and seeds better; mean arms; training-variance and per-model tables; plots.
  - `manzil/experiments/protocol_train.py`: Phase 4 trainer with training seed k and reward variant `base`/`fair`. For seed 0 it gives the same training log and dev score as `train_dqn.py` on a 3-episode check.
  - `manzil/experiments/protocol_corridor.py`: corridor v2 rerun on new seeds, with a development-vs-new contrast table.
  - `manzil/control/rl_env.py`: `last_starving` counter, used only for logging.
- **Models:** `models/dqn/grid3x3_base_s1`, `_base_s2`, `_fair_s0`, `_fair_s1`, `_fair_s2`. 200 episodes each, about 38 min each on CPU, dev scores 0.894–0.907. The Phase 4 model is unchanged and serves as base seed 0.
- **Protocol:** 560 runs (8 arms × 7 profiles × 10 seeds, 900 + 3,600 s). 0 failed, 0 safety violations, 0 collisions; 49 teleports in 4 runs.
  - **DQN (3-model average) vs tuned fixed-time, mean travel time incl. unfinished:**
    - light −10.4 %, medium −9.6 %, uneven −7.8 % (10/10 seeds each);
    - heavy −3.8 % [CI crosses 0], 9/10;
    - held out: uneven_ew −26.7 %, tidal −11.3 %, peak −11.1 % (10/10 each).
  - **Adaptive:** held-out −5 % to −18 %; light +0.7 %, uneven +2.8 %.
- **Training variance:** the three models agree within 0.1–2.8 s (between-model SD) on 6 of 7 profiles. On heavy they do not: s0 −22.6 s, s1 −13.4 s, s2 +16.7 s. s2 nearly gridlocked on seed 29 (372 s, 804 unfinished, 39 teleports).
- **Fairness variant** (starvation term at 60 s instead of 90 s; the 90 s term fired 0 times in base training):
  - Max red is lower: light 78.9 → 68.7 s and uneven 77.2 → 69.2 s (10/10 each).
  - No efficiency cost.
  - Heavy is stable: all 3 models beat fixed-time; the average is −9.8 % [−13.6 %, −6.0 %], 9/10.
  - Max red is still 59–79 s, against 30–55 s for fixed-time.
- **Corridor v2 on new seeds 20–29** (120 runs: 0 violations, 0 red crossings, 0 teleports):
  - v2 vs off: −34 % to −55 % ambulance time, 10/10 in all 4 settings.
  - v2 vs v1: −6 to −8 s with CI < 0 in 3 settings. Not confirmed on fixed-time heavy (−1.1 s [−16.5, 14.3], 5/10), the setting it was chosen on.

## Decisions
- Evaluation seeds 20–29, not 0–9: seeds 0–4 were already used to make FYP-1 decisions (corridor v2, the max-red guard).
- Held-out profiles live in a separate dict rather than in `PROFILES`, so `train_dqn.py`, `batch.py`, `check.py` and the API keep seeing only the training profiles. Only `ProtocolRunConfig` accepts them, which avoided editing `runner.py`.
- Fixed-time on held-out profiles uses the best **existing** plan on dev seeds (no new plans; `signals.json` is not W3's file). This favours fixed-time, which "knows" the demand. For uneven_ew no east–west plan exists, which inflates the DQN's gain there; this is recorded as a limit.
- Fairness variant = starvation threshold 60 s (c = 2 unchanged), fixed before any evaluation. The checkpoint-selection rule is the same as base (no fairness term in selection).
- DQN result reported as the average of 3 training seeds (`dqn_avg3`) plus each model separately; the Phase 4 single-model heavy number is no longer used as the estimate.
- Per-run CSVs (`signal_events.csv` etc.) are deleted after the fairness metrics are computed (they are git-ignored anyway).
